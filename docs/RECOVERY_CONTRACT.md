# v0.4 integration contract — recovery and existing-account invitations

Root owns HTTP, encrypted envelope, combined tests and publication. A owns auth invitations and the offline server-backup CLI. B owns workspace backup/retention semantics and organization storage transactions. C owns public UI. Existing Node default account boundary, synthetic demo and untouched Python reference remain. No public hosting/provider is implied.

## A — auth domain

Extend createAuth with invitePreview(token, {inviteToken}) -> {organization:{id,name},role,expiresAt,alreadyMember}; acceptInvite(token,{inviteToken}) -> {organization:{id,name,role},alreadyMember:boolean}; invitations(token,orgId) -> safe list {id,role,createdAt,expiresAt}; revokeInvitation(token,orgId,inviteId) -> {revoked:true}. Owners list/revoke only their club. IDs may be opaque digests (never raw codes); preview requires signed-in account, checks current issuer authority, does not consume. Accept atomic and one-use: already-member returns existing role without elevation and consumes code; bad/expired/revoked token generic400. No new user/password changes. Persistent safe old schema compatibility. Tests expiry/reuse, forgery, two clubs, last owner unaffected, concurrent consumption, failed writes. Root HTTP routes below.

## B — workspace semantics and durable restore

Own src/backup/workspace.mjs, src/organizations/index.mjs, tests/backup-workspace.test.mjs and tests/organization-recovery.test.mjs, docs/WORKSPACE_RECOVERY.md. Root independently writes src/backup/crypto.mjs; no circular crypto dependency.

Export createWorkspaceBackup({organizationId,organizationName,state,now}) -> plain bundle {format:'omniscout-workspace',version:1,organization:{id,name},createdAt,state,digest,summary}; inspectWorkspaceBackup(bundle,{organizationId,now}) -> {state,digest,summary}; stateDigest(state) -> sha256; retentionPreview(state,{now,days}) -> bounded, no-write report {asOf,days,counts,items,warnings,destructive:false}. Agree final summary fields in a message to root/C. Bound plain JSON to32MiB, bounded/depth-safe schema; no account, session or internal migration/restore credentials in club backup. Validate all known workspace fields, snapshots/digests, jobs, immutable history and references. Reject queued/running jobs in backups. Check current source export/store rights for ALL retained payloads, including rolled back snapshots and job payloads, on create AND restore; never let backup bypass expired/withdrawn/export-denied sources. Preserve original provenance and actor IDs. No silently dropping invalid data. Existing original legacy sanitizer may be factored for reuse but strict backup must reject unknown/dangerous fields rather than silently repair.

manager.capture(orgId) -> {state,digest}: serialize public operations, drain underlying queue, capture consistent isolated state. manager.restore(orgId,{state,expectedDigest,actor,backupDigest}) -> {restored:true,recoveryId,digest}: serialize, drain queue, verify current digest still equals preview, validate state again, refuse pending legacy migration. Save previous state as a durable private local recovery copy BEFORE atomic replacement, preserve internal migration receipt, append restore audit event. Never unlink current target. On failed commit old disk/memory remain. Keep at most10 recovery copies, refuse further restore rather than delete history. Copies share the active local state filesystem protection (not downloaded encrypted files); document that they are not disk encryption. Existing store/queue handles keep working after restore. No jobs silently start from backup. RecoveryId contains no file path. Memory mode keeps bounded private previous states. Idempotency enforced by root single-use preview token; concurrent changes must409. Tests real restart, disk/full/write errors, current state preserved, stale preview, wrong club, pending queue/migration, changed handles, bounded copies, unsafe paths/symlinks.

Retention is a preview ONLY: default365 days, integer1..3650. Distinguish age candidates, active dependencies, pending jobs and current rights blocks; do not claim deletion occurred or legal validity. Include older decisions/tasks/audit/history and source states, without leaking another club. Server returns owner-only. No automatic scheduling or deletion.

## Root encryption and HTTP

crypto.mjs exports sealBackup(bundle,passphrase) and openBackup(envelope,passphrase) with AES-256-GCM, random12-byteIV/16-byte salt, fixed scrypt parameters, authenticated fixed envelope metadata, validated base64 and bounded ciphertext. Passphrase15..128Unicode characters, no disk/log/session/browser-storage persistence. Generic bad password/tamper error. Bounded serialized crypto work and bounded request body. .osbackup is a JSON encrypted envelope; no plaintext club names or data in outer metadata.

Owner-only scoped routes (existing session, org header, CSRF): POST /api/backup/create {passphrase} returns encrypted file; POST /api/backup/preview {envelope,passphrase} -> {previewId,expiresAt,summary,currentSummary}; POST /api/backup/restore {previewId,confirm:true} -> manager restore result; GET /api/retention/preview?days=365 -> retention report. Preview stores decrypted state only in bounded temporary process memory for5min, bound to session+user+club; no mutation. Restore reauthorizes, checks current-state digest, consumes preview once. Logout/password rotation/expired session prevent reuse. Up to4 previews and bounded crypto concurrency; reject excess clearly.

Invitation routes: POST /api/auth/invite-preview {inviteToken}; POST /api/auth/accept-invite {inviteToken}; GET /api/auth/invitations and DELETE /api/auth/invitations/:inviteId owner-scoped. Preview/accept need signed-in account and CSRF, but no current club is needed; returned organization updates session/club selector through existing refresh.

## C — UI

Account & club gains invitation acceptance (explicit preview club/role then confirm), outstanding invite list/revoke, encrypted backup download, file+passphrase restore preview and explicit replacement confirmation, and retention days/report. Owners only for backup/restore/retention/invite administration. Backups clearly contain both demo+import of selected club, no accounts. Restore limited to same club; it replaces its scouting state, preserves roles/accounts, creates private local recovery copy. Clear file contents/password/preview on context switch/logout/navigation as appropriate; every request/download scoped and stale async guarded. Never put passphrases, files, decrypted state or codes in localStorage. Native desktop/mobile/keyboard compatibility and standalone/edge public demo remain. C owns the real browser suite tools/browser-recovery.mjs.

## Offline server backup

A implements separately from club-owner API: stopped-server administrative CLI, encrypted active accounts/memberships plus all active organization states, explicit manifest and hashes, staging validation, new empty destination only, original data never overwritten. No full-server backup through a club owner endpoint. Do not restore sessions or live invitation codes. Refuse running server, invalid state, unsafe paths and inconsistent claim; report exact exclusions and size limit. Test restore to a fresh directory and actual login/scouting data after restart. Real operational user backups are not created during development; synthetic temporary fixtures only.
